# UI: SLA-индикаторы обработки заявки

## Бизнес-требования

Оператор департамента проблемных активов должен видеть срок обработки заявки до ее отправки, чтобы не пропустить критичные обращения и правильно расставить приоритеты в очереди.

В форме реструктуризации необходимо добавить блок `SLA обработки`, где оператор указывает:

- дедлайн обработки;
- срочность;
- комментарий по SLA.

Система должна сразу показывать рассчитанный `SLA-статус`, чтобы оператор понимал, находится ли заявка в сроке, требует контроля или уже критична.

## Системные требования

Функциональность реализуется только во frontend без изменения backend DTO и REST API.

Поля блока:

| Поле | Тип UI | Обязательность | Значения / правило |
| --- | --- | --- | --- |
| Дедлайн обработки | `date` | Да | дата не может быть пустой |
| Срочность | `select` | Да | `Стандартная`, `Повышенная`, `Критическая` |
| Комментарий по SLA | `textarea` | Нет | произвольный текст |
| SLA-статус | readonly indicator | Нет | рассчитывается frontend |

Правило расчета SLA-статуса:

- дедлайн сегодня или в прошлом: `Критично`;
- дедлайн в пределах 3 календарных дней: `Под контролем`;
- дедлайн позже 3 календарных дней: `В срок`;
- пустой дедлайн: `Не задан`.

UI-поведение:

- блок отображается только в форме `Реструктуризация`;
- блок не отображается в форме `Банкротство`;
- статус пересчитывается при изменении дедлайна;
- при успешном создании заявки SLA-данные отображаются в карточке заявки в текущей frontend-сессии;
- payload в `POST /api/restructuring-cases` не меняется.

## Критерии приемки

- Пользователь видит блок `SLA обработки` в форме реструктуризации.
- Пользователь может выбрать дедлайн, срочность и заполнить комментарий.
- При пустом обязательном дедлайне форма не отправляется.
- При дедлайне в пределах 3 дней отображается `Под контролем`.
- После создания заявки карточка показывает дедлайн, срочность, SLA-статус и комментарий.
- Форма банкротства не содержит блок `SLA обработки`.
