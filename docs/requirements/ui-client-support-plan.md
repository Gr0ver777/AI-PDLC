# UI: План сопровождения клиента

## Бизнес-требования

Департамент проблемных активов должен фиксировать не только параметры реструктуризации, но и ближайший план сопровождения клиента. Это нужно, чтобы оператор и руководитель видели, кто отвечает за контакт с заемщиком, когда должен состояться следующий контакт и в каком состоянии находится пакет документов.

Оператор в форме реструктуризации должен заполнить блок `План сопровождения клиента`:

- дата следующего контакта;
- ответственный менеджер;
- канал связи;
- статус пакета документов;
- комментарий по сопровождению.

Бизнес-ценность:

- снижается риск потери следующего действия по проблемному активу;
- руководитель видит операционный контроль по заявке;
- QA может проверить новый функционал без зависимости от backend, так как MVP-фича frontend-only.

## Системные требования

Функциональность реализуется только во frontend без изменения backend DTO и REST API.

Поля блока:

| Поле | Тип UI | Обязательность | Значения / правило |
| --- | --- | --- | --- |
| Дата следующего контакта | `date` | Да | дата в формате браузера, поле не может быть пустым |
| Ответственный менеджер | `text` | Да | непустое строковое значение |
| Канал связи | `select` | Да | `Телефон`, `Email`, `Встреча`, `Мессенджер` |
| Статус пакета документов | `select` | Да | `Не запрошен`, `Запрошен`, `Получен частично`, `Получен полностью` |
| Комментарий по сопровождению | `textarea` | Нет | произвольный текст |

UI-поведение:

- блок отображается только в форме `Реструктуризация`;
- блок не отображается в форме `Банкротство`;
- обязательные поля используют встроенную browser validation;
- при успешном создании заявки введенный план отображается в карточке заявки в текущей frontend-сессии;
- payload в `POST /api/restructuring-cases` не меняется, поля плана сопровождения не отправляются в backend.

## Критерии приемки

- Пользователь видит блок `План сопровождения клиента` в форме реструктуризации.
- Пользователь может заполнить все поля плана сопровождения.
- Если обязательные поля блока пустые, форма не отправляется.
- После успешного создания заявки карточка отображает план сопровождения.
- Существующие happy-path сценарии реструктуризации и банкротства не ломаются.
