# QA Review: UI SLA-индикаторы обработки заявки

## Статус

`PASS_WITH_RECOMMENDATIONS`

## Проверка требований

- Бизнес-цель ясна: оператор должен контролировать срок обработки заявки.
- Пользователь определен: оператор департамента проблемных активов.
- Поля, обязательность и допустимые значения описаны.
- Правило расчета SLA-статуса тестопригодно.
- Ограничение frontend-only зафиксировано.
- Критерии приемки покрывают отображение, валидацию и карточку заявки.

## Риски

- SLA-данные пока не сохраняются в backend и теряются после перезагрузки страницы.
- Расчет использует календарные дни; при переходе к production может понадобиться банковский календарь и учет часового пояса.

## Рекомендации

- В ручном тест-кейсе проверить статусы `Критично`, `Под контролем`, `В срок`.
- В автотесте зафиксировать сценарий `Под контролем` как основной happy path.
- При backend-этапе добавить хранение SLA-полей и единое серверное правило расчета.

## Решение

Можно переходить к ручному тест-кейсу и UI-автоматизации.
