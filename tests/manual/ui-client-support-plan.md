# Manual TC: План сопровождения клиента в реструктуризации

## Цель

Проверить frontend-only блок `План сопровождения клиента` в форме реструктуризации.

## Предусловия

- Frontend запущен на `http://localhost:5173`.
- Backend может быть недоступен: для проверки допустим Playwright route mocking.

## Тестовые данные

- Клиент: `ООО Автотест Реструктуризация`
- ИНН / ID: `7701999001`
- Сумма долга: `2500000`
- Просрочка: `75`
- Дата следующего контакта: `2026-06-01`
- Ответственный менеджер: `Иван Петров`
- Канал связи: `Телефон`
- Статус пакета документов: `Запрошен`
- Комментарий: `Согласовать дату звонка и проверить комплектность документов`

## Шаги

1. Открыть рабочую панель AI-PDLC.
2. Перейти в раздел `Реструктуризация`.
3. Проверить, что отображается блок `План сопровождения клиента`.
4. Очистить обязательные поля `Дата следующего контакта` и `Ответственный менеджер`.
5. Нажать `Создать заявку`.
6. Заполнить обязательные поля плана сопровождения валидными значениями.
7. Нажать `Создать заявку`.
8. Проверить карточку созданной заявки.
9. Перейти в раздел `Банкротство`.
10. Проверить, что блок `План сопровождения клиента` не отображается.

## Ожидаемый результат

- На шаге 5 форма не отправляется из-за browser validation.
- На шаге 8 карточка содержит блок `План сопровождения клиента` и введенные значения.
- На шаге 10 блок не отображается в форме банкротства.

## Результат ручной проверки

`PASS_WITH_MOCK`

Проверка выполняется через Playwright route mocking, потому что фича frontend-only и не требует готового backend-контракта.
